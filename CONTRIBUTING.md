# Como contribuir com o Tripeiro

Relatos de problemas, sugestões, correções de informação e exemplos fictícios que ajudem a investigar uma falha são bem-vindos. Siga o [guia de suporte](SUPPORT.md) para escolher o formulário e acompanhar a resposta.

**Neste momento, somente colaboradores convidados podem abrir Pull Requests.** Isso não impede usuários com conta no GitHub de abrir ou comentar nas issues públicas. Para sugerir uma alteração de texto ou de comportamento, descreva-a em uma issue; não é necessário enviar código.

O aplicativo é desenvolvido em um repositório privado. Este repositório distribui a skill e mantém o canal público de suporte. Não é necessário ter acesso ao código do app para participar.

## Para colaboradores convidados

Antes de implementar, consulte as issues e combine escopo e critérios de aceite com o mantenedor. Use uma branch `codex/` e uma worktree exclusivas, criadas a partir da main atualizada. Preserve alterações existentes e faça as mudanças por PR para main, incluindo documentação e validações pertinentes. Não faça push direto na main nem merge sem autorização do mantenedor.

Siga o [plano aprovado](docs/suporte-publico.md) quando a tarefa fizer parte dele. Para atualizar a distribuição da skill e executar os checks, consulte [manutenção do repositório](docs/manutencao-repositorio.md). Os PRs exigem o check de integridade aprovado e conversas resolvidas; o merge é manual por squash.

Nunca inclua credenciais, arquivos pessoais, roteiros reais ou dados de usuários no código, exemplos, testes, issues ou PRs. Falhas de segurança são tratadas conforme [SECURITY.md](SECURITY.md).

Mantenha a conversa respeitosa e siga o [código de conduta](CODE_OF_CONDUCT.md).
